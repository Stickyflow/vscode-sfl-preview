Technical documentation

The diagram and its text, always in sync.

vscode-sfl-preview renders an .sfl document next to its source with stickyflow.js. The extension host owns the document and the filesystem, a sandboxed webview owns rendering and canvas gestures, and the two only talk through a small sfl/* message protocol.

Host / webview split One panel per document Edits are text edits Prebuilt stickyflow.js Strict CSP

Goals and principles

The preview is a thin layer over stickyflow.js. Its own code is mostly wiring: which side owns which state, and how changes cross the boundary without loops or lost edits.

01

The text is the truth

Every canvas change becomes new SFL text, written back as a WorkspaceEdit. It lands on the undo stack and in your diff like any edit.

02

Clear ownership

The host owns the document, save dialogs and file writes. The webview owns the viewer, camera, selection and gestures.

03

One panel per URI

Previews are keyed by document URI. Re-running the command reveals the existing panel, like the built-in Markdown preview.

04

Update, never remount

External edits go through viewer.update(), so pan, zoom and edit-mode bindings survive every keystroke.

05

Renderer as static assets

stickyflow.js is copied from its dist/ at build time. The extension host itself has no runtime dependencies.

06

Typed against the renderer

Webview modules see stickyflow.js only through its .d.ts types. A renamed or removed export fails npm run compile instead of blanking the panel. Pure logic stays separate from DOM glue.

Two extensions, one document

vscode-sfl understands the text, vscode-sfl-preview draws it. They never call each other: both react to the same .sfl document, and installing either one installs both.

Host and webview

Two runtimes with a hard boundary. Anything that needs VS Code or the filesystem stays in the host; anything that needs the DOM stays in the webview.

The webview's CSP is default-src 'none' with a per-load nonce and 'strict-dynamic'. The nonce authorizes the inline bootstrap; 'strict-dynamic' extends that trust to everything it imports: media/webview/main.js and its modules, and the code-split chunk-*.js files stickyflow.js imports, which a bare nonce would block.

Message protocol

Everything that crosses the boundary. Messages are plain objects, validated by shape on the receiving side. In the webview, webview/host.ts declares both directions as types and is the only place that calls postMessage.

MessageDirectionPayload and effect
sfl/updatehost → webviewsource, likelyExternalRewrite. Debounced 150 ms. Calls viewer.update() with change highlighting (blue for a likely external rewrite).
sfl/selecthost → webviewid of the innermost block at the cursor, or null. Calls viewer.select().
sfl/editwebview → hostFull patched source. Applied as one whole-document WorkspaceEdit, skipped when unchanged.
sfl/revealwebview → hostid of the selected shape or link. Moves the editor selection to its header line without stealing focus.
sfl/sceneDiffwebview → hostadded, removed, changed. Shown as a 3 second status bar message.
sfl/warnwebview → hostmessage. Explains a canvas action that could not be applied.
sfl/exportwebview → hostformat (svg or png) and data. Host opens a save dialog and writes the file.
Selection sync is bidirectional, and each side's action triggers the other side's event. Both sides remember the last synced owner id and skip a sync that would only restate it, which breaks the loop without a separate "programmatic change" flag.

A canvas edit, step by step

Dragging a shape in edit mode, from pointer event to the text editor and back.

01

Gesture

With Editing: On, bindEditing() from stickyflow.js's interaction tier emits a moveChange for each moved owner. A batcher collects the gesture's moves until the next microtask.

editMode.ts → stickyflow/interaction → editActions.ts
02

Patch the text

withoutNestedMoves() drops moves whose ancestor frame also moved (children are relative to their parent), then the rest fold through applyMoveChange() into one new source string.

moves.ts → session.objects() → applyMoveChange()
03

Update locally, then report

doc.commit() updates the viewer immediately without highlighting (you just watched it happen) and sends sfl/edit with the full source.

session.ts commit() → viewer.update() → host.edit()
04

Write the document

The panel replaces the whole document in one WorkspaceEdit. The patchers already preserve comments and formatting, so a narrower diff would add nothing.

panel.ts → applyEditToDocument()
05

Echo, ignored

The edit fires onDidChangeTextDocument, which schedules an sfl/update. doc.receive() sees the source equals the one it holds and does nothing.

extension.ts → SflPreviewPanel.updateIfOpen() → scheduleUpdate()

Build pipeline

npm run compile runs three steps. stickyflow.js must be built first in its sibling checkout.

B1

Copy the renderer

The whole dist/ tree is copied, because the ESM entries import sibling chunk-*.js files by relative path. SOURCE.json records the stickyflow.js version, branch and commit that was copied.

npm run copy-media
B2

Compile the host

src/ compiles to out/ with the main tsconfig.json.

tsc -p ./
B3

Compile the webview

webview/ compiles to a cleared media/webview/ as ES2022 modules with DOM types, type-checked against the copied stickyflow.js .d.ts files.

npm run compile:webview

Design decisions

Trade-offs made deliberately, and what they cost.

D1

Shape-based rewrite guess

VS Code does not say who made an edit. One large change at the top of the file is treated as an external rewrite and flashed in blue.

  • Cost: git checkout or select-all paste look the same.
src/extension.ts
D2

Own block scanner

Selection sync uses a small line scanner instead of importing stickyflow.js into the host.

  • Cost: approximate, but reveal has a low correctness bar.
src/sflOwnerBlocks.ts
D3

Export re-renders

Export calls render() on the current source instead of serializing the live SVG, whose viewBox follows pan and zoom.

  • Cost: one extra render per export.
webview/exportDiagram.ts
D4

Inject, don't import

The webview modules never import stickyflow.js at runtime. The bootstrap passes its namespaces in, and the modules type them from the copied .d.ts. No bundler, no import paths that differ between source and output.

  • Cost: the types are only as current as the last copy-media.
webview/stickyflow.ts, webview/main.ts

Quality checks

Pure logic is unit tested in Node. The real webview is driven in headless Chrome.

Vitest covers the owner-block scanner used for selection sync.
Vitest covers link route patching and pan geometry in webview/__tests__/.
tsc -p tsconfig.webview.json checks every webview module against stickyflow.js's types.
npm run verify:webview loads the generated HTML in headless Chrome.
It exercises panning, edit mode, dragging, resizing and link routing end to end.
Run npm run check (compile, unit tests, verify:webview) after touching getWebviewHtml.ts or anything in webview/. It needs a local Chrome (set CHROME_PATH if needed) and skips itself when none is found.
